# Severity & Confidence Guide

Reviewer sub-agents 和主 session 在评估 issue 时使用此指南统一判断标准。

---

## Severity 四级定义

### Critical（必须修复，阻断合并）

会导致以下后果之一：
- **安全漏洞**：凭证泄漏、注入攻击、认证绕过
- **数据丢失 / 损坏**：未处理的数据库错误、缺少事务
- **系统崩溃**：未处理的异常传播到顶层、空指针在关键路径
- **生产中断**：破坏性变更缺少迁移、API 合约被破坏

**Examples**:
- 源代码中硬编码了 AWS Secret Key
- 用字符串拼接构造 SQL 查询（SQL 注入）
- 支付流程中缺少错误处理，失败时仍扣款

---

### High（应在本次修复）

会导致以下后果之一：
- **性能严重退化**：N+1 查询、大表全表扫描
- **隐性 bug**：竞态条件、边界值错误（可能低概率触发）
- **资源泄漏**：文件句柄 / 连接未关闭（长期运行会耗尽资源）
- **可靠性风险**：外部调用无超时 / 重试（网络抖动会卡死）

**Examples**:
- 循环内每次查询数据库（应批量）
- goroutine / thread 操作共享变量无锁
- 未关闭的数据库连接

---

### Medium（记录但不在本轮修复）

- 可维护性负担：重复代码、函数过长
- 潜在但低概率的 bug：部分路径缺少 null 检查
- 技术债：废弃 API 使用、过时依赖

---

### Low（记录，供参考）

- 纯代码风格：命名风格、注释措辞
- 小优化建议：可读性改进
- 文档缺失

---

## Confidence 评分标准

| 分值 | 含义 |
|------|------|
| 0.90 – 1.00 | 确定是 bug，能精确定位到行，Fix 方案明确 |
| 0.75 – 0.89 | 很可能是 bug，但需要查看调用方或运行时上下文才能完全确认 |
| 0.60 – 0.74 | 可疑，依赖不在 diff 内的上下文，不建议自动修复 |
| < 0.60 | 猜测性结论，直接丢弃 |

**默认处理阈值**：`confidence_threshold = 0.70`  
低于阈值的 issue 进入"已知但不修"清单，不触发修复。

---

## 决策树

```
这个 issue 是否存在于本次 diff 引入的代码中？
├─ No  → In-scope = No，直接丢弃
└─ Yes → 继续 ↓

会产生安全风险？
├─ Yes → Critical
└─ No  → 继续 ↓

会导致数据丢失 / 系统崩溃 / 生产中断？
├─ Yes → Critical
└─ No  → 继续 ↓

会造成性能严重退化 / 资源泄漏 / 可靠性隐患 / 高概率隐性 bug？
├─ Yes → High
└─ No  → 继续 ↓

可维护性负担 / 低概率潜在 bug / 技术债？
├─ Yes → Medium（进入"已知但不修"清单）
└─ No  → Low（进入"已知但不修"清单）
```

---

## Blast Radius 与 Confidence 联动

修复前主 session 评估影响范围：

| Impact | 规则 |
|--------|------|
| `LOW` | 仅函数内部，不改签名 → Confidence 不变 |
| `MEDIUM` | 影响模块内多函数，不改公开接口 → Confidence 不变 |
| `HIGH` | 改变公开 API / 接口 / 跨模块 → **Confidence -= 0.15** |

若调整后 Confidence 低于 `confidence_threshold` → 跳过，标注 `Blocked: High Impact`。
